# Pinpoint: Project Brief

*Hackathon project brief for a 2-person
team. Status: agreed scope, ready to build.*

## 1. Problem statement

Students spend hours re-reading notes,
which feels productive but works poorly. They can't tell what they truly
understand, and what they do learn fades within days.

**Formal version:**

Students rely on passive study methods like
re-reading, which give a false sense of understanding. They have no quick way
to find out which parts of a topic they actually don't know, and even material
they understand is forgotten within days. Existing tools tackle one side only
(flashcards, notes, timers). **Pinpoint** puts two proven techniques in one
loop: **speaking a topic out loud to expose gaps (active recall / Feynman
technique)** and **pinning each idea to a familiar place (memory palace /
method of loci)** so it sticks.

**One-line pitch:** *Stop re-reading. Explain it, find the gaps, then pin it to a
place you can't forget.*

## 2. Who it's for

Students anywhere in the world, at any
pace. One account type, no teacher role.

•
**Fast learner:** wants to learn more in less time. Moves quickly through Explain and
builds large palaces.

•
**Deep learner (own pace):** takes time to understand. Uses Explain to close gaps one by one,
then pins only what they've understood.

Avoid the word "slow" in the UI
and the pitch. Say "learns at their own pace."

## 3. The core loop

1.
**Add a topic:** upload a PDF or photos (max 2 pages).

2.
**Explain it:** speak for a chosen time (1 to 5 minutes). AI compares it with the
material.

3.
**See the gap map:** covered, partial, incorrect, missing, plus a score.

4.
**Fix and retry** the gaps.

5.
**Pin it:** place a flag for each key idea on a photo of a familiar place.

6.
**Recall:** flags are hidden, the student recalls each within a time limit, and
flags turn green or red.

Explaining comes before pinning on purpose:
a memory palace built on a half-understood idea only helps you remember
confusion.

## 4. App structure

Sign up or log in, then land on the
dashboard. A **bottom bar** has five tabs: **Home | Topic | Explain |
Palace | Recall**.

### Home (dashboard)

•
Greeting: "Hey {student
name}".

•
**Units and notes:** all previously learned units with topic cards (title, mastery ring,
notes created by the student or generated by AI).

•
**Task list:** completed and not completed. Tasks are **auto-generated** per
topic, not hand-typed:

o
Add material: done when a file
is uploaded

o
Explain it: done when an
explanation scores at or above the pass mark (default 70%)

o
Pin it: done when at least one
flag is linked to the topic

o
Recall it: done when the latest
recall round is mostly green

•
**Calendar:** exam dates marked, plus one **large number showing days left to
the nearest exam** (color shifts from calm to amber to red as the date
approaches).

### Topic

•
Student adds documents, PDFs,
or pictures they want to learn. **Maximum 2 pages** (enforced on the server:
count PDF pages, cap images at 2).

•
On upload, the AI extracts a **title,
a short notes summary, and 5 to 8 key points.** The student can edit the key
points before saving. These key points are the checklist for Explain.

### Explain

•
Student picks a topic and picks
a recording time (for example 1, 2, 3, or 5 minutes) with a visible countdown.

•
Live transcript while speaking
(browser Web Speech API), with a **typed fallback** if voice fails.

•
AI checks the transcript
against the key points and shows **how far off the student is** (for example
"You covered 5 of 8 key points"), a score ring, and a gap map.

•
Buttons: **Retry the gaps**
and **Pin the gaps** (sends missing points to the Palace).

### Palace

•
**Grid** of places, each a photo tile with its name and flag count.

•
**Place view:** the photo with multiple flags on it (zoom and pan). Tapping a flag
opens a **side panel** showing what the flag holds, with an **Edit**
button at the bottom. On mobile, the side panel becomes a bottom sheet.

•
**Add flag:** tap Add flag, tap a spot on the photo, enter the information
(optionally link it to a topic's key point).

•
**Add place:** take or upload a new photo, name it, then add flags.

### Recall mode

•
Picks a **random place** the
student already created.

•
The student sets the **time
allowed per flag.**

•
Flags are hidden. The student
taps a flag and tries to recall it within the time.

•
Result colors: **green** =
recalled within the time, **red** = not recalled (including timeout).

•
Grading is **self-graded with
a timer** by default (reveal the answer, then "Got it" or
"Missed").

•
The photo ends as a heatmap of
green and red flags.

**AI notes:**

•
Note: a Gemini app subscription
is separate from API access. The team needs an **API key** from Google AI
Studio (a free tier exists; check current limits in the dashboard).

•
Keep the key in a server .env, add .env to .gitignore
before the first commit, and never expose it in React code.

•
Use a fast Flash-class model,
and keep the model name in an env variable.

•
Request **JSON-only output**,
validate it, and retry once if malformed.

•
The AI judges **meaning, not
exact keywords.** A simple keyword matcher is the fallback if the API fails.

•
Compute the score in code, not
in the AI: covered = 1, partial = 0.5, incorrect and missing = 0.

•
Free-tier prompts may be used
by Google for training, so don't send personal details.

## 8. How the Explain AI call works

1.
The client sends the
transcript.

2.
The server builds a prompt with
the topic notes, the numbered key points, and the transcript, and tells the AI
that the transcript may contain speech-recognition errors.

3.
For each key point the AI
returns a status (**covered, partial, incorrect, missing**), a short
evidence quote, and one sentence of feedback, plus a one-line summary and the 1
to 2 most important gaps.

4.
The server validates the JSON,
computes the score, saves it, and returns it.

5.
The client animates each key
point to green, amber, or red.

Guard rails: block submissions under
roughly 15 words, judge only against the uploaded material, let the student
edit the transcript before submitting.

## 13. Demo plan (about 2 minutes)

1.
**Hook (15s):** "Re-reading doesn't work. Explaining does, and so does your
own room."

2.
**Explain (40s):** Explain a topic aloud, deliberately skipping one part. The gap map
shows what's missing.

3.
**Fix (15s):** Re-explain the missing part and watch the score rise.

4.
**Pin (30s):** Photograph a desk and drop flags for the key ideas.

5.
**Recall (15s):** Hide the flags, recall them against the timer, and one turns red.

6.
**Close (5s):** "Explain it. Pin it. Own it."

Prepare one seeded demo account with a
topic, a place, and flags, and measure a before-and-after quiz score on
yourselves to quote one real number honestly.
