**Explain it. Pin it. Own it.**

Pinpoint helps students learn faster by combining two proven techniques in one loop: speaking a topic out loud to expose gaps (active recall), and pinning each idea to a photo of a familiar place so it sticks (memory palace).

> Built for a hackathon by a team of two. Stack: PostgreSQL, Express, React, Node (PERN), plus the Gemini API.

## The problem

Students spend hours re-reading notes, which feels productive but works poorly. They cannot tell which parts of a topic they truly understand, and what they do learn fades within days.

Existing tools tackle one side only (flashcards, notes, timers). Pinpoint connects two techniques:

1. **Teach It Back:** explain a topic aloud and see exactly which key points you covered, got wrong, or missed.
2. **Memory Palace:** pin each key idea to a spot in a photo of a place you already know, then test your recall against a timer.

## How it works

1. **Add a topic:** upload a PDF or photos (max 2 pages).
2. **Review key points:** AI extracts a title, summary, and 5 to 8 key points. Edit them if needed.
3. **Explain it:** choose a recording time and speak. A live transcript appears.
4. **See the gap map:** each key point is marked covered, partial, incorrect, or missing, with a score.
5. **Retry the gaps** until the score improves.
6. **Pin it:** add a flag for each key idea on a photo of a familiar place.
7. **Recall:** flags are hidden. Recall each one within your chosen time. Flags turn green or red.

Explaining comes before pinning on purpose: a memory palace built on a half-understood idea only helps you remember confusion.

## Features

**Home (dashboard)**
- Greeting with the student's name
- Units and topics with mastery rings (notes written by the student or generated by AI)
- Auto-generated task list (add material, explain, pin, recall)
- Exam calendar with a large countdown to the nearest exam

**Topic**
- Upload PDFs or images, with a server-enforced limit of 2 pages
- AI key-point extraction, editable before saving

**Explain**
- Choose a topic and a recording time
- Live voice-to-text (with a typed fallback)
- AI gap analysis, score, and retry flow
- "Pin the gaps" sends missing points to the Palace

**Palace**
- Grid of places (photos you took)
- Place view with multiple flags, zoom, and pan
- Side panel (bottom sheet on mobile) showing flag details, with an Edit button
- Add place and add flag flows

**Recall mode**
- Random place from the student's palace
- Student-defined time limit per flag
- Green for recalled in time, red for not recalled
- End-of-round heatmap of weak flags

## Architecture

```
┌─────────────────────────────────────────────┐
│ React PWA (mobile first)                    │
│ Home | Topic | Explain | Palace | Recall    │
│ Browser Web Speech API for voice            │
└──────────────────────┬──────────────────────┘
                       │ HTTPS + JWT
                       ▼
┌─────────────────────────────────────────────┐
│ Express API                                 │
│ Auth, routes, validation, scoring           │
└───────┬───────────────┬───────────────┬─────┘
        ▼               ▼               ▼
   PostgreSQL      File storage     Gemini API
 (users, topics,  (photos, PDFs)   (extract key points,
  flags, ...)                       check explanations)
```

The browser never talks to the database, storage secrets, or Gemini directly. Everything goes through the Express API, and every query is scoped to the logged-in user.

## Getting started

### Prerequisites

- Node.js 18 or later
- A PostgreSQL database (a free Neon or Supabase project works well)
- A Gemini API key from [Google AI Studio](https://aistudio.google.com) for document extraction
- Cloudinary is optional; local uploads are stored in `server/uploads`
- Chrome or Edge for voice input (other browsers can use typed explanations)

> A Gemini app subscription is separate from API access. You need an API key from AI Studio.

### 1. Clone the repository

```bash
git clone <your-repo-url>
cd pinpoint
```

### 2. Install and configure

```bash
npm run install:all
```

Copy `server/.env.example` to `server/.env` and `client/.env.example` to `client/.env`. Set a valid PostgreSQL `DATABASE_URL` and a long random `JWT_SECRET` in `server/.env`. A Gemini API key is required for AI document extraction; Explain falls back to keyword matching when Gemini is unavailable. Cloudinary is optional for local development.

### 3. Migrate, seed, and run

```bash
cd server
npx prisma migrate dev --name init
npm run seed
npm run dev
```

In a second terminal:

```bash
cd client
npm run dev
```

The API runs at `http://localhost:4000`; Vite prints the client URL (normally `http://localhost:5173`).

### 4. Demo and mock mode

The seed creates `demo@pinpoint.app` and `demo2@pinpoint.app`; the local demo password is `PinpointDemo123!`. Change these credentials before exposing a seeded environment publicly. The first demo account includes a sample topic, place, flags, and an upcoming exam.

To run the client without the API or database, set `VITE_USE_MOCK=true` in `client/.env` and start Vite. The mock API keeps its sample data in memory.

### Tests

```bash
cd server && npm test
cd client && npm test && npm run build
```

With a migrated database and the API running, run `bash server/scripts/test-palace.sh` from the repository root for Palace HTTP integration checks.

### Exam calendar and motion

The authenticated app shell includes an accessible monthly exam calendar on desktop and mobile. It uses the existing owner-scoped `GET /exams` endpoint (including each exam's optional unit as its subject); exam create, edit, and delete mutations refresh the calendar through React Query. Add an optional time and subject/unit on the dashboard to show them in calendar details. Page transitions, calendar marks, progress, and recall-streak feedback honor `prefers-reduced-motion`.

### Windows desktop launcher

Run `powershell -ExecutionPolicy Bypass -File scripts\install-shortcut.ps1` to place the Pinpoint shortcut and branded icon on your Desktop. Double-click it to start whichever local services are not already healthy and open the dashboard in an Edge/Chrome app window. Close that app window to stop services started by the launcher; pre-existing services are left running. Logs are written to `logs\`.

To uninstall, delete `Pinpoint.lnk` from your Desktop. If port 4000 (API) or 5173 (Vite) is occupied by a non-Pinpoint process, stop that process or update the port values in `scripts\pinpoint-launcher.ps1`. A responding Pinpoint service is reused rather than duplicated.

## API overview

All routes except signup, login, and health require `Authorization: Bearer <token>`.

| Area | Routes |
|---|---|
| Auth | `POST /auth/signup`, `POST /auth/login`, `GET /me`, `PATCH /me` |
| Dashboard | `GET /dashboard` |
| Units | `GET /units`, `POST /units`, `PATCH /units/:id`, `DELETE /units/:id` |
| Topics | `GET /topics`, `POST /topics`, `GET /topics/:id`, `PATCH /topics/:id`, `DELETE /topics/:id` |
| Files | `POST /topics/:id/files`, `POST /topics/:id/extract`, `DELETE /topics/:id/files/:fileId` |
| Explain | `POST /topics/:id/explain`, `GET /topics/:id/explanations`, `GET /explanations/:id` |
| Places | `GET /places`, `POST /places`, `GET /places/:id`, `PATCH /places/:id`, `DELETE /places/:id` |
| Flags | `POST /flags`, `PATCH /flags/:id`, `DELETE /flags/:id` |
| Recall | `POST /recall/start`, `POST /recall/:roundId/reveal`, `POST /recall/:roundId/result`, `POST /recall/:roundId/finish`, `GET /recall/history` |
| Exams | `GET /exams` (authenticated, returns each exam with its optional unit/subject), `POST /exams`, `PATCH /exams/:id`, `DELETE /exams/:id` |
| System | `GET /health` |

### Example: explain a topic

Request:

```json
POST /topics/12/explain
{ "transcript": "Plants absorb sunlight using chlorophyll...", "duration_sec": 120 }
```

Response:

```json
{
  "score": 63,
  "summary": "Solid start. Fix the oxygen source and add the light reactions.",
  "points": [
    { "id": 1, "status": "covered",   "feedback": "Good." },
    { "id": 2, "status": "incorrect", "feedback": "Oxygen comes from splitting water." },
    { "id": 3, "status": "missing",   "feedback": "Explain the light reactions." }
  ],
  "next_focus": [2, 3]
}
```

## Data model

```
users(id, name, email, password_hash)
units(id, user_id, title)
topics(id, user_id, unit_id, title, notes, key_points_json, mastery)
topic_files(id, topic_id, file_url, type, page_count)
explanations(id, topic_id, transcript, duration_sec, score, points_json, created_at)
places(id, user_id, name, image_url)
flags(id, place_id, topic_id, key_point_id, x, y, title, note, emoji)
recall_rounds(id, user_id, place_id, time_limit_sec, started_at)
recall_results(id, round_id, flag_id, result, seconds_taken)
exams(id, user_id, unit_id, title, exam_date)
```

Notes:
- Flag `x` and `y` are percentages (0 to 100) of the image, so flags stay aligned on any screen size.
- Key points live as JSON on the topic, each with a stable id. Flags and explanation results reference those ids.
- Dashboard tasks are computed from existing data, not stored.

## Scoring logic

The AI judges meaning, but the score is calculated in code so it is consistent and explainable.

| Status | Weight |
|---|---|
| `covered` | 1 |
| `partial` | 0.5 |
| `incorrect` | 0 |
| `missing` | 0 |

```js
const score = Math.round(
  (points.reduce((sum, p) => sum + weights[p.status], 0) / points.length) * 100
);
```

A topic's "Explain it" task is complete when the score meets the pass mark (default 70%).

### AI reliability

- Gemini is asked for JSON-only output, which the server validates against a schema and retries once if invalid.
- If Gemini fails or times out, a keyword matcher takes over (lower quality, but the app keeps working).
- The explain and upload routes are rate limited to protect the API quota.

## Deployment

| Piece | Suggested host |
|---|---|
| Frontend | Vercel |
| API | Render or Railway |
| Database | Neon or Supabase |
| Files | Cloudinary or Supabase Storage |

Steps:
1. Deploy the database and run `npx prisma migrate deploy`.
2. Deploy the API with all server environment variables set.
3. Deploy the client with `VITE_API_URL` pointing at the deployed API.
4. Set `CLIENT_URL` on the server to the deployed frontend origin.
5. Seed a demo account, and ping `/health` before presenting, since free tiers can sleep.

## Known limitations

- Voice input uses the browser Web Speech API, which works in Chrome and Edge only. A typed fallback is always available.
- Recall grading is self-graded against a timer.
- Uploads are limited to 2 pages per topic.
- Free-tier Gemini prompts may be used by Google for training, so avoid sending personal details.
- Scoring depends on AI judgment and can occasionally misjudge a point. Students can edit the transcript before submitting.
